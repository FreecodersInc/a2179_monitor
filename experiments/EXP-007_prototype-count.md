## Вопрос и гипотеза
H-06: «Прототипов достаточно ~15 на сторону: удвоение меняет F1 TF-IDF канала < 0.01, половина роняет > 0.03». Удвоить нечем (новых прототипов нет), поэтому проверяем только половину.
До прогона: половина прототипов (случайно, с каждой стороны, 5 подвыборок) роняет held out F1 tfidf+feat больше чем на 0.03 в среднем на A2179. Опровержение: падение < 0.01. На вакансиях правило recall 1.0 вырождается (EXP-006), там меряем при `--min-recall 0.0` и считаем это разведкой.

## Условия и установка
Вложенная CV как в EXP-004 (5 фолдов, группы, 12 повторов, sweep правило ничьей). Меняется только набор прототипов для tfidf и bm25. Признаки, regex и gate не трогаем. Dense каналы не считаем.

## Процедура
```bash
for s in 0 1 2 3 4; do python eval/nested_cv.py --dense-dir /nonexistent --repeats 12 --proto-frac 0.5 --proto-seed $s --name half_$s --out reports/exp007; done
python eval/nested_cv.py --dense-dir /nonexistent --repeats 12 --name full --out reports/exp007
```
и то же с `--target de_jobs --min-recall 0.0`.

## Выводы
* **H-06 на A2179: inconclusive.** Падение tfidf+feat 0.029: больше порога опровержения 0.01, но меньше заявленных 0.03. Реальных FP становится больше на 2.5…3.5 при каждой из 5 половин, направление стабильное, величина на границе.
* **Неожиданное (разведка, не заявлялось):** для BM25 важнее, *какие* прототипы, чем сколько. Одна половина роняет bm25 до F1 0.456 (102 FP), другая поднимает до 0.911 (7 FP, лучше полного набора). Значит в списке прототипов A2179 есть такие, что вредят BM25. Это вопрос для H-20 (расширение и отбор прототипов), подбирать список на этих же 430 строках нельзя, только с отложенной пачкой.
* **Вакансии:** половина прототипов ничего не меняет (±0.005), канал держится на признаках профиля (EXP-006). Это разведка, правило max F1.

## Угрозы валидности
* 5 подвыборок, разброс между ними больше эффекта для bm25.
* Удвоение не проверено: новых прототипов нет.
* Прототипы писались с оглядкой на эти данные (как в EXP-004).
