## Вопрос и гипотеза (до прогона)

На раннере, не на нашей машине, проверяем гипотезы, которые в EXP-027 остались blocked из-за размера моделей. GPU в этом прогоне не используем, она нужна только для H-11 (отдельная запись EXP-029).

* **H-04.** Cross-encoder или NLI вопрос «продаётся ли здесь X» на top-k после bi-encoder поднимает dense P при R 1.0 минимум на 0.15. Опровержение: прирост < 0.05. Здесь NLI: `MoritzLaurer/multilingual-MiniLMv2-L6-mnli-xnli`. Гипотеза для NLI (одна и та же на всех строках): «This listing sells a MacBook Air A2179 LCD screen. Ovaj oglas prodaje LCD ekran za MacBook Air A2179.» Скор строки = вероятность entailment. База для прироста: лучший чистый dense из уже посчитанных на тех же реальных строках, иначе BM25 (`sim_pos - sim_neg`).
* **H-13.** Многоязычный cross-encoder (mMARCO) поднимает P@R95 над лучшим прозрачным hybrid (tfidf+feat) минимум на 0.05. Опровержение: прирост < 0.02. Модель: `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`. Скор строки = max CE(положительный прототип, заголовок+сниппет) минус max CE(отрицательный прототип, заголовок+сниппет). Считаем на всех реальных строках (кандидаты H-12 уже не держат R 0.99, EXP-024).
* **H-19.** SPLADE против BM25 даёт ≤ 0.02 P@R1. Опровержение: SPLADE ≥ BM25 + 0.05. Модель: `naver/splade-v3-distilbert` (полный набор в одном репозитории). Скор = max sparse-скалярного произведения к положительным прототипам минус к отрицательным.
* **H-23.** ColBERT даёт dense pure P@R1 минимум на 0.10 выше MiniLM. Опровержение: прирост < 0.03. Модель: `answerdotai/answerai-colbert-small-v1`. Если не загрузится, запись «недоступна», ColBERTv2 не берём в этом же прогоне, чтобы не держать две тяжёлые модели.

## Условия и установка

* Только CPU. Перед шагом `CUDA_VISIBLE_DEVICES` пустой. H-11 в этом EXP не гоняется.
* Одна модель в памяти. После каждой: `del`, `gc.collect()`, при наличии torch `torch.cuda.empty_cache()`, затем удаление именно этого репозитория из кэша HF раннера, чужие модели (MiniLM монитора и т.п.) не трогаем.
* Перед загрузкой проверка свободных RAM и диска. Если свободно меньше чем 2×веса + 1 GiB RAM или веса + 2 GiB диска, модель пропускаем с причиной, не качаем.
* Тексты объявлений в артефакты не пишем (ADR-0032), только метрики и идентификаторы моделей.
* Файлы результатов ≤ 50 MiB.
* Команда на раннере, не у нас:

```bash
python eval/exp028_blocked_models.py --out reports/runner_exp/runner-exp-2026-11-20-v2 --device cpu
```

`--dry-run` только планирует и ничего не качает (локальная проверка синтаксиса).

## Выводы

* **H-04 refuted.** NLI P@R1 0.046 против MiniLM 0.067 (прирост −0.021) и против BM25 0.097, оба < 0.05. NLI mMiniLM в монитор не берём.
* **H-13 refuted.** mMARCO P@R95 0.110 против TF-IDF 0.159 из того же артефакта, прирост −0.049 < 0.02. Зарегистрированная база tfidf+feat в этом артефакте не посчитана, она могла быть только не ниже лексического TF-IDF, зазор бы не сократился. mMARCO L12 в монитор A2179 не берём.
* **H-19 accepted.** SPLADE P@R1 0.097 как у BM25, прирост 0.000 ≤ 0.02 (опровержение было бы от +0.05). По AP SPLADE выше (0.368 против 0.225), но правило записано по P@R1. SPLADE в монитор не берём, остаётся BM25.
* **H-23 refuted.** ColBERT P@R1 0.062 против MiniLM 0.067 на тех же 371 строке, прирост −0.005 < 0.03. ColBERT-small в монитор не берём.

## Угрозы валидности

Реальных позитивов 17, интервалы широкие. H-13 сравнивался с TF-IDF без признаков, потому что tfidf+feat в `exp028.json` нет. H-19 по P@R1 совпадает с BM25, при этом R@npos и AP у SPLADE выше, это не меняет заранее записанное правило. MiniLM для H-04 и H-23 взят из `dense_scores.jsonl` того же прогона, не из повторной загрузки модели внутри `exp028_blocked_models.py`.
