## Вопрос и гипотеза
Может ли похожесть (TF-IDF, BM25, плотный эмбеддер MiniLM, их смеси) отличить «объявление продаёт нужный товар» от «объявление про ту же тему» (та же модель ноутбука, но шарниры, стекло, сервис, «куплю»)?
Гипотеза (Лёня): нет, как и в RAG retrieval, косинус меряет, *про что* текст, а не *что* в нём продаётся. Опровержение: dense канал с P ≥ 0.9 при R = 1.0.

## Условия и установка
- Каналы: regex монитора, char 3..5 gram TF-IDF, word BM25 (k1 1.5, b 0.75, IDF по прототипам), MiniLM `paraphrase-multilingual-MiniLM-L12-v2`, явные признаки товара (слова дисплея +1, каждая группа других деталей, аксессуаров, сервиса, «куплю» −1).
- Скаляр канала d = cos_pos − cos_neg (max по прототипам), min-max по набору. Смеси: w·A + (1−w)·B, w = 0 … 1 шагом 0.1, RRF k = 60, признаки весом lam = 0 … 1 шагом 0.1.
- pure = только похожесть (с model gate), hybrid = regex OR похожесть. Порог: лучший F1 при recall 1.0.

## Процедура
```bash
python eval/sweep.py                    # всё, кроме dense
python eval/sweep.py --compute-dense    # плюс MiniLM (нужен эмбеддер), не прогонялось
python eval/run_eval.py                 # прогон Лёни с MiniLM (лог в reports/raw/)
```

## Результаты
| вариант | P | R | FP | откуда |
|---|---|---|---|---|
| regex | 0.976 | 0.976 | 1 | sweep |
| TF-IDF pure | 0.808 | 1.000 | 10 | sweep |
| BM25 pure | 0.750 | 1.000 | 14 | sweep |
| TF-IDF + признаки (lam 0.1) pure | 0.857 | 1.000 | 7 (0 на реальных строках) | sweep |
| MiniLM pure | 0.600 | 1.000 | 28 | прогон Лёни |
| hybrid regex + TF-IDF | 0.977 | 1.000 | 1 | sweep и прогон Лёни |
| hybrid regex + BM25 | 0.955 | 1.000 | 2 | sweep |
| hybrid RRF(TF-IDF, BM25) | 0.955 | 1.000 | 2 | sweep |
| hybrid regex + MiniLM | 0.840 | 1.000 | 8 | прогон Лёни |

- 28 FP у MiniLM: 12 других деталей, 7 аксессуаров, 2 сервиса, 2 «куплю/ищу», 2 целых ноутбука, 2 ноутбука с разбитым экраном, 1 другая модель. 13 из 28 реальные объявления. |cos_pos − cos_neg| ≤ 0.069 у всех 28, у 18 из 28 разница отрицательная. Шарниры «Šarke za ekran MacBook Air A2179»: 0.959 к дисплейному прототипу.
- Не прогонялось: dense sweep по порогу, lin(dense, BM25) при w = 0.1 … 1.0, RRF(dense, BM25), dense + признаки. Косинусы есть только для ошибочных строк прогона Лёни.
- Выбрано в конфиг: hybrid TF-IDF pos 0.34, margin 0.16 (середина плато с 1 FP), эмбеддер выключен.

## Выводы
1. Гипотеза Лёни подтверждается на этих данных: MiniLM путает тему с товаром, все 28 ложных срабатываний про «ту же модель + деталь/намерение».
2. BM25, линейные смеси и RRF не дали ничего сверх лучшего канала. Помогает явный признак товара (то, что продаётся), а не другая похожесть.
3. В hybrid почти всё решает regex: похожесть нужна ровно для одной строки (id 62), единственный общий FP (id 96) идёт от regex.

## Угрозы валидности
99 строк, 59 синтетических, все трудные негативы, которые остаются у hybrid MiniLM, синтетические. Одна модель (обучена на парафразах, не на асимметричном поиске), сравнение с прототипами через max cos, без cross-encoder реранкера. Пороги подобраны на тех же данных (частично проверено 2-fold и 5-fold). Вывод «эта модель в такой постановке не отличает товар от темы», а не «эмбеддеры не работают».
