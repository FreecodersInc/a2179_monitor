## Вопрос и гипотеза
Сколько из того, что матчер de_jobs отдаёт, реально DE или соседняя роль, и сколько он пропускает, когда поток уже не 112 вакансий с двух досок, а тысячи с ATS.
**Это разведочный прогон, не предрегистрированный.** H-33 и её порог записаны после того, как сбор и разметка уже были видны, поэтому «опровергнута» тут читается как описание того, что увидели, а не как проверка. Предрегистрированная проверка будет H-34 на следующей пачке.
H-33 (записана после прогона): точность матчера ≥ 0.70 по E+S, а полнота по E+S ≥ 0.50. Критерий: верхняя граница 95% интервала полноты ниже 0.50.

## Условия и установка
* **Пачка стратифицирована**: все 206 строк, где матчер сказал match (страта `matcher`), 3 трудных негатива (score ≥ 0.3), и 141 равномерно случайная строка из оставшихся 2977 (seed 0). Строки, уже размеченные в первой пачке, исключены.
* **Пул уже отфильтрован по заголовку** (`a2179/ats.py`, TITLE_RX: data, analytics, platform, devops, sre, cloud, ml, ai…), поэтому случайная страта не «все вакансии компании», а только технические заголовки рядом с доменом. Полнота здесь меряется относительно этого пула.
* **Метки**: все 350 ставил ассистент (`labeler = bot`, ADR-0024) только по заголовку, компании и локации, по правилу из `eval/de_jobs/README.md`. 18 спорных в `eval/de_jobs/uncertain_b2.md`. Это не независимая разметка, автор меток видел правила профиля.
* **Метрики**: P на страте matcher (Wilson 95%). Пропущенные позитивы в пуле = доля позитивов в случайной страте × 2977 (Wilson по доле, умножено на пул). R = найдено / (найдено + пропущено). Два вида меток: E+S (как label в наборе) и только E (строгое чтение «DE роль»).

## Процедура
```bash
python -m eval.review_run --cases de_jobs --out-root data/scratch_reports   # 4 прогона по 85 с бюджета, пока все 155 досок не в кэше
python eval/jobs_label.py sheet --reports data/scratch_reports --max 350 --seed 0
python eval/jobs_label.py merge
python eval/strata_eval.py
```

## Выводы
* **H-33 (разведочно) не держится по полноте E+S**: R 0.12, верхняя граница 0.15 < 0.50, при любом решении по 18 спорным. Точность 0.66–0.72 в зависимости от спорных.
* Опровержение в основном про S. Профиль держит DevOps, SRE, Platform, ML engineer среди позитивных прототипов, а матчер их почти не берёт. Либо S не должна быть позитивом для Лёни, либо матчеру нужен уровень `adjacent`. Это вопрос к профилю, а не к модели.
* По строгому E полнота 0.40 с широким интервалом, и почти весь промах это один шаблон заголовка: software engineer + data platform или data infrastructure.
* Toronto и Vancouver: в пуле 173 вакансии (Toronto 125, Vancouver 48), матчер отдал 6.

## Угрозы валидности
* Первая версия считала вариант «E+S без спорных», просто выкидывая 18 строк из страт. Это неверно: спорные не случайная часть своей страты, и перевес по пулу после такого выброса смещён. Заменили на проверку чувствительности: все спорные позитив, потом все негатив, выборка не прореживается.
* Метки бот, по заголовку, без текста. Автор меток писал правила профиля (смещение в пользу матчера, то есть реальная полнота скорее ниже).
* Полнота относительно пула после TITLE_RX: то, что префильтр выкинул, не видно вовсе.
* Случайная страта 141 строка, интервалы по E широкие.
* Одна дата сбора, ATS доски крупных компаний (Databricks один даёт заметную долю).
