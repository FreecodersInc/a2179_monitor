## Вопрос и гипотеза (до прогона)
На 462 AUC cv_score 0.880, на свежих 150 0.656 (EXP-011, EXP-020). Это переобучение числовых настроек профиля или другой состав свежей пачки?

**H-44.** Если числа профиля подбирать только на train фолдах, held out AUC на 462 ≥ 0.85, то есть 0.880 держится не на подгонке чисел. Опровержение: < 0.80, тогда 0.880 в основном подгонка.

**Проверка состава (заявлена до прогона).** Свежая пачка набрана по стратам правил на заголовке (match и rest по 75), в ней много C (68 из 150). Если AUC на 462 внутри страты match ≤ 0.75 и близка к batch3 внутри match (разница ≤ 0.05), разрыв объясняется составом, а не переобучением.

## Условия и установка
* Что подбирается внутри фолда: веса четырёх частей cv_score (skills, stack, domain, seniority) на симплексе шаг 0.1 (286 вариантов), шкала домена (значение для каждого класса правил = доля позитивов этого класса на train со сглаживанием 1/2), насыщение стека из {5, 10, 15, 20}. Выбор по AUC на train.
* Что не подбирается и остаётся утечкой: сами правила классов, список обязательных навыков и список стека писались, когда эти строки уже были видны. Эту часть вложенная CV не снимает, её снимает только свежая пачка, поэтому отдельно: настройка на всех 462, проверка на batch3.
* Внешний цикл 5 фолдов, стратификация по позитиву, 10 повторов. AUC на test пулом по фолдам, среднее по повторам. Рядом ручной профиль (как в EXP-020) на тех же фолдах.
* Позитив: E или S по `esci_text`.

## Что прочитано и как это повлияло
* **Varma, Simon 2006, Bias in error estimation when using cross-validation for model selection** ([BMC Bioinformatics 7:91](https://doi.org/10.1186/1471-2105-7-91)): оценка CV для классификатора, чьи параметры подобраны той же CV, заметно смещена вверх, на «пустых» данных давала ошибку < 30% там, где на независимых данных был уровень случайности. Вложенная CV, где подбор повторяется в каждом внешнем фолде, даёт почти несмещённую оценку. Отсюда правило: весь подбор чисел внутри фолда, и отдельная независимая проверка на batch3 для той части, которую повторить внутри фолда нельзя (ручные правила).

## Результаты
Прогон `eval/nested_cv_jobs.py`, итог в `reports/exp023/nested_cv_jobs.json`. 462 строки (позитивов 211), свежих 150 (позитивов 64), тексты есть у всех.

| что | AUC |
|---|---|
| ручной профиль на 462 (как EXP-020) | 0.880 |
| **вложенная CV, числа подобраны внутри фолда** (5 фолдов × 10) | **0.916** (повторы 0.901 до 0.925) |
| AUC на train при подборе (среднее) | 0.941 |
| подбор на всех 462, проверка на свежих 150 | 0.690 (95% 0.602, 0.775) |
| ручной профиль на свежих 150 | 0.657 |

Подбор на всех 462 выбрал веса skills 0, stack 0.2, domain 0.7, seniority 0.1, насыщение стека 20. То есть почти всё держится на классе правил по заголовку.

**Страты (заявлено до прогона).** Ручной профиль: 462 внутри match 0.876 (128 строк), rest 0.812 (334). Свежие внутри match 0.658 (75), rest 0.688 (75). Внутри match на 462 AUC выше 0.75 и далеко от свежих (разница 0.218), значит объяснение «другой состав по стратам match и rest» **опровергнуто**.

**После прогона, не заявлялось (описательно).** Доля позитивов по классам правил, 462 против свежих: strong 90/92 против 2/2, ml_sre_infra 61/89 против 25/58, devops 19/20 против 18/31, none 37/222 против 15/48, ai_platform 1/17 против 4/6. AUC ручного профиля внутри класса: ml_sre_infra 0.714 против 0.701, devops 1.000 против 0.489, none 0.798 против 0.622. Без класса strong: 462 0.814 (370 строк) против свежих 0.646 (148).

## Выводы
* **H-44 принята.** Вложенная CV даёт 0.916 ≥ 0.85, подгонка чисел профиля не объясняет 0.880.
* Но перенос на свежие не держится: даже подобранный на 462 профиль даёт на свежих 0.690. Разрыв не в числах, а в данных. В 462 есть 92 строки класса strong (Data Engineer в заголовке), почти все позитивы, их легко отделить. В свежей пачке таких 2, а внутри трудного класса ml_sre_infra AUC совпадает (0.714 и 0.701). Разница сидит в devops и none, где на свежих метка по тексту чаще расходится с заголовком.
* Для H-35 это значит: «0.880 это переобучение» неверно в смысле подгонки, но высокий AUC на 462 держится на лёгком классе, на трудных строках cv_score около 0.70. Статус H-35 не меняется: refuted на свежих данных.

## Угрозы валидности
Ручные правила, обязательные навыки и стек писались с этими строками в поле зрения, вложенная CV это не снимает. Метки по тексту ставил один разметчик (бот), второго нет. Анализ по классам сделан после прогона.
