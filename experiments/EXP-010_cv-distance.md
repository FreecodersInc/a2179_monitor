## Вопрос
Настоящая задача кейса вакансий (Лёня, 2026-11-20): не «DE или нет», а насколько каждая вакансия близка к его опыту, как спека экрана в A2179, только сложнее. Метки E/S/C/I нужны только чтобы проверить, что расстояние меряет правильное.

## Скор (зафиксирован до прогона, веса не подбираются по меткам)
`cv_score = 0.30 skills + 0.30 stack + 0.25 domain + 0.15 seniority`, части в [0, 1]:
* skills: доля из трёх обязательных пунктов профиля в заголовке и описании (SQL, Python или Scala, одно из Spark / Airflow / ETL / dbt)
* stack: сколько терминов стека профиля найдено, насыщение на 15
* domain: семья роли по правилам профиля v2: DE 1.0, соседние роли 0.8, Data Science 0.5, weak 0.3, иначе 0
* seniority: senior, staff, lead, principal 1.0, без уровня 0.9, менеджер и директор 0.4, стажёр и junior 0.2

## Гипотеза H-35 (до прогона)
cv_score отделяет позитивы (E+S) от C+I с AUC ≥ 0.80, ранжирует по степени E > S > C > I со Spearman ≥ 0.50, и во вложенной CV (порог по max F1 на train) канал `dense:cv` не хуже канала признаков профиля больше чем на 0.02 F1.
Опровержение: AUC < 0.70, или Spearman < 0.30, или `dense:cv` хуже feat only больше чем на 0.05 F1.
Дополнительно (без порога): AUC каждой части отдельно, чтобы видеть, что тянет.

## Угрозы, видные заранее
* Метки ставились по заголовку, а skills и stack смотрят в текст, домен смотрит в тот же заголовок, что и метки. Ожидаем, что domain сам по себе даст большую часть AUC, это надо показать, а не прятать.
* Метки бот. Эталон не всё CV, а одобренный профиль навыков.

## Результаты
462 строки, у всех есть описание из кэша ([cv_distance.md](../reports/exp010/cv_distance.md)).

| часть | AUC (E+S против C+I) |
|---|---|
| skills | 0.718 |
| stack | 0.805 |
| domain | 0.931 |
| seniority | 0.670 |
| **cv_score** | **0.902** |

Spearman cv_score со степенью E > S > C > I: 0.776.
Вложенная CV ([cv_nested.md](../reports/exp010/cv_nested.md)): dense:cv F1 0.861 (P 0.834, R 0.890), dense:cv+feat 0.860, feat only 0.879, tfidf+feat 0.876.

## Вердикт
H-35 держится по всем трём заявленным порогам: AUC 0.902 ≥ 0.80, Spearman 0.776 ≥ 0.50, F1 на 0.018 ниже feat only (порог 0.02, впритык).

Оговорки:
* domain один даёт AUC 0.931, выше общего скора. Он смотрит в заголовок, а метки ставились по заголовку, поэтому это частично одно и то же. Веса заранее не подбирались и не будут подбираться по этим меткам.
* Часть по тексту (stack) сама AUC 0.805, это и есть «близость к опыту», которую метки по заголовку не видят. Проверить её честно можно только метками по полному тексту.
* Эталон одобренный профиль навыков, полное CV в репо нет. Скор с полным CV возможен только локально, в репо только агрегаты.

## Вариант B: стек из полного CV (заявлено 2026-11-20 до прогона)
Теперь полное CV в репо (`cv/master_cv.md`, ADR-0035). Вариант B меняет только часть stack: термины берутся из раздела «Technical and Delivery Skills» CV (через запятую), а не из профиля. Остальные части и веса те же, по меткам ничего не подбирается.
Ожидание: AUC cv_score в пределах ±0.02 от варианта A (0.902), AUC части stack не ниже 0.78. Опровержение «полное CV ничего не меняет»: AUC cv_score отличается от A больше чем на 0.03 в любую сторону, тогда смотрим, какие термины CV тянут.
```bash
python eval/cv_distance.py --stack-from cv/master_cv.md --out reports/exp010_b
```

### Результат варианта B
96 терминов стека из CV ([cv_distance.md](../reports/exp010_b/cv_distance.md), [cv_nested.md](../reports/exp010_b/cv_nested.md)).

| | A (профиль) | B (полное CV) |
|---|---|---|
| AUC cv_score | 0.902 | 0.904 |
| AUC stack | 0.805 | 0.773 |
| Spearman по степени | 0.776 | 0.772 |
| F1 dense:cv, вложенная CV | 0.861 | 0.863 |

Вердикт: cv_score держится в пределах ±0.02 (0.904), это как ожидали. Вторая часть ожидания не выполнена: AUC stack 0.773 < 0.78. Стек из CV шире (робототехника, наблюдаемость, общие слова вроде logs, metrics, estimates), он ловит больше не DE вакансий. Метки ставились по заголовку, поэтому честное сравнение A и B ждёт метки по полному тексту (T-032).
