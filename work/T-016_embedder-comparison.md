## Цель
Одним прогоном понять, тянет ли какой то мультиязычный эмбеддер сербский лучше MiniLM (H-30), и честно сравнить лучший из них с базой без ML: правила + явные признаки + очередь спорных на человека (H-31). Если база без ML не хуже, эмбеддер в мониторе не нужен.

## Критерии приёмки
- [x] реестр моделей `eval/embedders.json`: id, префиксы, размер, лицензия, влезает ли в 2 GB, проверено на huggingface.co
- [x] `eval/sweep.py --embedders none|all|cached|список` считает все модели в одном прогоне, каждая как канал `dense:<short>`, упавшая модель пропускается с причиной, CUDA OOM переходит на CPU
- [x] таблица моделей рядом: P@R1, P@R95 с 95% bootstrap интервалом, 5-fold, real only (`sweep.tables.md`, `plots.md`)
- [x] `ci/cache_model.py` кэширует список моделей, только нужные файлы. CI: `A2179_CI_MODELS` для кэша, `A2179_CI_EMBEDDERS=cached` для свипа
- [ ] прогон на раннере с 4 моделями из EXP-003, числа в EXP-003
- [ ] ≥ 50 строк на кириллице в наборе (enrich), иначе вывод про sr_cyr не делаем
- [ ] no ML база (H-31): парсер атрибутов в профиле, очередь спорных, замер размера очереди на потоке монитора
- [ ] статусы H-30, H-31, H-17 в `HYPOTHESES.md`, при смене модели монитора ADR вместо ADR-0007

## План
1. Лёня кэширует модели (`python ci/cache_model.py ...`), CI сам подхватит их через `cached`.
2. Сравнить с MiniLM по H-30, с no ML базой по H-31.
3. Если выигрыш эмбеддера меньше разброса интервалов, оставить монитор на правилах + TF-IDF и вкладываться в парсер атрибутов и очередь.
