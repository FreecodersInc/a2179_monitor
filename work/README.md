# work: майлстоуны и задачи

Здесь планируем работу. Майлстоун = заметный результат (например «набор eval на 500 реальных объявлений»), задача = одна проверяемая единица работы внутри него.

Как пользоваться:
- Майлстоун: скопировать [`MILESTONE_TEMPLATE.md`](MILESTONE_TEMPLATE.md) в `work/M-NNN_<коротко>.md`.
- Задача: скопировать [`TASK_TEMPLATE.md`](TASK_TEMPLATE.md) в `work/T-NNN_<коротко>.md`, указать майлстоун.
- Номера не переиспользуются, файлы не удаляются: закрытая задача остаётся со статусом `done` или `dropped` и причиной.
- Каждая задача ссылается на то, что её подтверждает: коммиты, эксперименты (`experiments/EXP-NNN`), решения (`docs/adr/NNNN`). Исследовательская задача без EXP записи не закрывается, решение без ADR тоже.
- Добавить строку в индекс ниже.

Прогоны экспериментов на GPU делает CI на раннере Лёни, числа появляются в `results/` ([docs/ci.md](../docs/ci.md)). В задаче ссылайся на файл результата.

Статусы: `todo`, `in progress`, `blocked`, `review`, `done`, `dropped`.
