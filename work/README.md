# work: майлстоуны и задачи

Здесь планируем работу. Майлстоун = заметный результат (например «набор eval на 500 реальных объявлений»), задача = одна проверяемая единица работы внутри него.

Как пользоваться:
- Майлстоун: скопировать [`MILESTONE_TEMPLATE.md`](MILESTONE_TEMPLATE.md) в `work/M-NNN_<коротко>.md`.
- Задача: скопировать [`TASK_TEMPLATE.md`](TASK_TEMPLATE.md) в `work/T-NNN_<коротко>.md`, указать майлстоун.
- Номера не переиспользуются, файлы не удаляются: закрытая задача остаётся со статусом `done` или `dropped` и причиной.
- Каждая задача ссылается на то, что её подтверждает: коммиты, эксперименты (`experiments/EXP-NNN`), решения (`docs/adr/NNNN`). Исследовательская задача без EXP записи не закрывается, решение без ADR тоже.
- Добавить строку в индекс ниже.

Прогоны экспериментов на GPU делает CI на раннере Лёни, числа появляются в `results/` ([docs/ci.md](../docs/ci.md)). В задаче ссылайся на файл результата.

Статусы: `todo`, `in progress`, `blocked`, `review`, `done`, `dropped`.

## Порядок

Сначала унификация пайплайна, потом прогоны гипотез. Решение: [ADR-0017](../docs/adr/0017-two-case-eval.md).

1. **Унификация** (выше по приоритету): [M-001](M-001_configurable-targets.md) (цель задаётся профилем) и [M-003](M-003_de-job-search.md) (английские вакансии Data Engineer: Канада Toronto / Vancouver / remote Canada и EU remote на английском). Публичный профиль `targets/de_jobs.json`, личный остаётся в `targets/de_jobs.local.json` (gitignore).
2. **Честная проверка A2179 на свежих реальных лотах** (до любых новых моделей): признаки и порог tfidf+feat, mpnet+feat замораживаются отдельным коммитом, Лёня руками размечает свежую партию реальных объявлений, которых не было в наборе, и на ней одной сравниваются tfidf+feat, mpnet+feat и реранк. Причина: на 430 строках пороги подобраны на том же наборе, а среди реальных строк всего 17 позитивов (tfidf+feat 7 FP, mpnet+feat 8 FP, разница в одну строку). Потом реранк [T-009](T-009_rerank-stage.md) с кандидатами из ранжирования без ML, и в конце большие эмбеддеры (bge-m3, e5-large, e5-large-instruct, LaBSE) с кэшем оценок, чтобы повторный прогон их не пересчитывал.
3. **Прогоны гипотез** [M-002](M-002_research-plan.md): каждая гипотеза H-01…H-32, включая сравнение эмбеддеров H-30 / EXP-003 и no ML базу H-31, проверяется в `reports/` параллельно на двух кейсах: `targets/a2179_screen.json` (экран ноутбука) и `targets/de_jobs.json` (английские вакансии). Гипотезу не закрываем, пока нет чисел по обоим, либо в EXP явно записано, почему один кейс ещё нельзя.

Разницу между кейсами не записываем как эффект языка, пока не закрыт контроль [T-022](T-022_language-domain-control.md) / H-32.

Выход для ручной проверки: `python eval/review_run.py` (и шаг `review` в CI) пишет `reports/<дата>/a2179_screen/` и `reports/<дата>/de_jobs/`: `matches.csv` / `matches.md` (совпадения) и `all.csv` / `all.md` (все скачанные), поля title, company, location, score, decision, url, fetched_at. Экран берётся из `eval/candidates_*.jsonl`, вакансии из Remotive и Remote OK (кэш 24 часа). Полный eval/свип с метриками по вакансиям по-прежнему ждёт набор T-019.
