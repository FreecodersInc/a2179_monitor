# Отчёт по проекту a2179_monitor: состояние на 2026-11-20 (черновик, правим вместе с Лёней)

Два кейса по ADR-0017: `a2179_screen` (экран A2179 на сербских досках) и `de_jobs` (английские вакансии Data Engineer, Канада и remote). Всё ниже сделано по одному стандарту: гипотеза и критерий опровержения записаны до прогона, пороги выбираются только на train, числа берутся из CI (`results/`) или из команды в EXP записи.

## 1. Коротко
1. **ML пока не нужен ни на одном кейсе.** На A2179 regex профиля один держит held out F1 0.948, лучшая связка tfidf+feat 0.908, лучший эмбеддер (mpnet+feat) ничья с tfidf, MiniLM монитора хуже на 3 реальных FP (EXP-004). На вакансиях лучший канал это признаки профиля без ML, F1 0.743, MiniLM ничего не добавляет (EXP-006).
2. **Правило порога «recall 1.0 на всём размеченном» слабое место на обоих кейсах.** На A2179 оно сидит на одном двух трудных позитивах (EXP-008: на 100 строках train FP меньше, F1 выше). На вакансиях оно недостижимо. Gate профиля закрывает 67 из 207 позитивов (почти все S роли), поэтому recall 1.0 нельзя получить ни при каком пороге (EXP-006). Gate, правило и порог должны жить в профиле цели и совпадать с тем, что считаем позитивом.
3. **Матчер вакансий точный в ядре и слепой по краям.** Data Engineer и Analytics Engineer ловит почти идеально, но полнота по E+S около 0.12 (SRE, DevOps, ML engineer, platform почти не берёт), по строгому DE около 0.40, и главный промах это «Software Engineer, Data Platform» (EXP-005, разведка).
4. **Источники вакансий выросли с 112 до 3298 после дублей** за счёт 155 публичных ATS досок (ADR-0025), Toronto и Vancouver 173 вакансии.
5. **Новое определение позитива вакансий (SRE, DevOps, ML engineer да, 2026-11-20).** Профиль v2: gate закрывает 12 позитивов из 213 вместо 67. Лучший канал опять признаки профиля без ML, F1 0.879, MiniLM+feat 0.874, regex v2 один 0.727 (P 0.969, R 0.582) (EXP-009). Data Science как позитив отдельным вариантом: F1 0.903.
6. **Главная гипотеза вакансий H-35, близость к опыту кандидата, держится** (EXP-010): скор по skills, stack, domain, seniority от профиля навыков даёт AUC 0.902, Spearman по степени 0.776, во вложенной CV 0.861 против 0.879 у признаков. Больше всего тянет domain по заголовку, часть по тексту описания stack AUC 0.805. Полного CV в репо нет.
7. **Честная проверка A2179 на свежих лотах началась, но данных мало** (T-023): CI собрал свежую пачку без правки workflow (ADR-0022), новых лотов всего 13, все отрицательные, заморозка 0 FP. Позитивов 0, порог и прототипы размораживать не на чем, копим дальше.

## 3. Что сделано
* **Профиль цели** вместо зашитого A2179 (M-001, T-001, T-002, T-004): eval, sweep и CI по каждой цели.
* **CI** на раннере Лёни: тонкий workflow, вся логика в `ci/`. Выбор шагов по диффу (ADR-0026): docs без прогона, общий код полная регрессия, остальное lint, тронутые тесты и свой эксперимент. `paths-ignore` и `cancel-in-progress` в workflow Лёня поставил сам (cb6f6a3).
* **Оценка**: вложенная CV с группами дублей (`eval/nested_cv.py`), заморозка каналов под свежую пачку (`eval/freeze.py`, `eval/frozen/a2179_screen.json`), оценка стратифицированной пачки с перевесом к пулу (`eval/strata_eval.py`).
* **Вакансии**: Remotive, Remote OK, Greenhouse, Lever, Ashby. Вежливо: пауза 1 с, кэш 24 часа, бюджет на прогон, потолок ответа, в кэше только отфильтрованное.
* **Разметка вакансий**: 462 строки (112 + 350), все поставил ассистент (`labeler = bot`, ADR-0024), 33 спорных вынесены отдельно.

## 5. Гипотезы
* Проверены: H-15 (A2179 да, вакансии нет), H-06 inconclusive (EXP-007), H-14 вторая часть держится (EXP-008), H-17 опровергнута, H-30 inconclusive, H-31 частично (оба кейса: ML не нужен, но на вакансиях одного regex мало), H-33 разведка.
* H-35 (главная для вакансий) держится, H-36 (ансамбль эмбеддеров, планка +0.03 F1) записана и стоит до скоров больших моделей с раннера и свежей пачки.
* Предрегистрированы и ждут данных: H-34 (правило под «Software Engineer + Data Platform», проверка на следующей пачке), T-023 (заморозка A2179 против свежей пачки).
* Не тронуты, потому что нужны данные, которых нет: H-07 (второй разметчик, κ), H-10 (всего 4 кириллические строки), H-32 (нужен перевод сербских лотов), H-09 (нужны цены у ≥ 150 строк), большие эмбеддеры (ждут свежую пачку A2179).
* Остальные H-01…H-29 в статусе planned: их можно гонять на текущих 430 строках вложенной CV, но каждый такой прогон это ещё один выбор на тех же данных. Предлагаю сначала T-023, потом брать по одной.

## 7. Угрозы валидности
* Все метки de_jobs поставил автор правил профиля, по заголовку, без текста вакансий.
* На A2179 всего 17 реальных позитивов, разница между каналами в одну две строки.
* Прототипы и группы признаков писались с оглядкой на те же данные, вложенная CV этого не чистит.
* Эмбеддеры на вакансиях только MiniLM.
* Профиль v2 писался после того, как мы видели пачку 2, всё про v2 на `labeled.jsonl` это числа на тех же данных. Честно только пачка 3 (T-025).
* Матчер A2179 видит заголовок и сниппет, а сниппет есть у 21 из 430 строк. Полная карточка объявления следующий шаг (T-031).
