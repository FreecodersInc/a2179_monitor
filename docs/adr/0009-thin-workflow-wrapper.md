# ADR-0009: workflow как тонкая обёртка без actions, вся логика в ci/

## Контекст и проблема
Первый прогон (run #1, коммит 4ee8426) упал на старте: политика организации FreecodersInc разрешает только actions из репозиториев FreecodersInc, а YAML звал `actions/checkout@v4` и `actions/upload-artifact@v4`. Вторая проблема: токен Telega не может писать в `.github/workflows`, каждую правку YAML Лёня копирует руками. Цель: Telega итерирует CI сам, обычными пушами.

## Факторы решения
* YAML должен меняться как можно реже (идеально никогда)
* работать при политике «только свои actions»
* те же гарантии: только push в main, только эта репа, `contents: write`, без чужого кода
* токен не оседает на диске раннера

## Рассмотренные варианты
* попросить разрешить actions от GitHub в настройках организации (меняет политику ради нас, YAML всё равно толстый)
* форк actions/checkout в FreecodersInc (ещё одна репа на поддержку)
* один шаг без `uses:`: `git fetch` пушнутого sha, `checkout -B main`, `exec bash ci/run.sh`, всё остальное в `ci/`

## Решение
Третий вариант. В YAML только триггеры, guard, права, concurrency, timeout, runner labels и один шаг. В шаг передаются `GITHUB_TOKEN` и весь `vars` как JSON (`A2179_CI_VARS`), `ci/run.sh` сам берёт нужные `A2179_CI_*`. Токен идёт в git через `GIT_CONFIG_*` только в окружении процесса. Артефакта нет, отчёты коммитятся рядом с результатом в `results/<base>/`. `ci/write_results.py` работает на системном python (stdlib), поэтому результат пишется даже при сломанном venv, и в каждом результате есть `workflow_in_sync`.

### Последствия
* Хорошо: правки CI это обычные пуши в `ci/`, новые настройки это переменные репы, копировать YAML больше не нужно.
* Хорошо: не зависит от политики actions.
* Плохо: свой checkout проще, чем actions/checkout (нет submodules, LFS, sparse), здесь не нужны.
* Плохо: нет артефактов в UI Actions, отчёты лежат в `results/`, репа растёт на несколько десятков КБ за прогон.
* Граница доверия та же: кто пушит в main, тот исполняет `ci/run.sh` на машине Лёни.

### Как проверяем
`tests/test_ci.py`: в YAML нет `uses:`, из секретов только `GITHUB_TOKEN`, один шаг, заканчивается `exec bash ci/run.sh`. Bootstrap прогоняется на локальной bare репе (тот sha, ветка main, `git clean`, токена нет в `.git/config`, повторный прогон в той же папке). `ci/run.sh` целиком на готовом venv и при сломанной установке (результат всё равно пишется).
