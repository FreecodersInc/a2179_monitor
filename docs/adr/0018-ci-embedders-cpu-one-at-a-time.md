# ADR-0018: эмбеддеры в CI считаются на CPU, по одной модели, с ограничением памяти

## Контекст и проблема
Несколько эмбеддеров подряд на MX130 (2 ГБ видеопамяти) вылезли из GPU в общую RAM через PCI и повесили всю машину Лёни. Нужно, чтобы обычный прогон CI сравнивал модели и при этом не клал хост.

## Факторы решения
* машина с раннером не должна зависать из-за свипа
* несколько моделей в одном прогоне всё ещё нужны для EXP-003
* GPU можно вернуть явно, когда прогон к этому готов
* прогресс в логе должен быть виден по ходу, а не только в конце

## Рассмотренные варианты
* оставить GPU по умолчанию и уменьшить только батч
* считать на CPU, но держать несколько моделей в памяти сразу
* по умолчанию CPU, одна модель за раз, маленький батч, мало потоков, память между моделями освобождать

## Решение
Третий вариант (коммит 2cf7478):

* `A2179_CI_DEVICE=cpu` по умолчанию: CUDA спрятана от шагов (`CUDA_VISIBLE_DEVICES=`), GPU никто не трогает. Значение `cuda` вернёт GPU
* `A2179_CI_THREADS` по умолчанию половина ядер, но не больше 4, для torch, MKL и OpenBLAS
* `A2179_CI_EMBED_BATCH=16`
* модели грузятся строго по одной, между ними `del` и `gc`, в логе строка `dense i/N <модель>` на каждую

Какие модели входят в обычный прогон, см. ADR-0019.

### Последствия
* Хорошо: свип больше не обязан трогать 2 ГБ GPU и не должен вешать машину.
* Хорошо: GPU остаётся доступен явной переменной, когда понадобится.
* Плохо: прогон на CPU медленнее, чем на видеокарте. Это цена стабильности хоста.

### Как проверяем
Повторяющийся свип на раннере не вешает машину. В логе есть строка на каждую модель, после модели память отдаётся. `docs/ci.md`, раздел «Эмбеддеры в CI на CPU».
