# ADR-0002: фильтр = regex OR похожесть с model gate, recall first

## Контекст и проблема
Монитор должен не пропустить ни одного объявления с нужным товаром (экран, крышка, донор под A2179) среди объявлений «про ту же модель» (другие детали, аксессуары, сервис, «куплю»). Пропуск хуже лишнего уведомления.

## Факторы решения
* recall важнее precision
* объяснимость: почему объявление прошло или нет (`reasons`)
* работа без тяжёлых зависимостей

## Рассмотренные варианты
* только regex
* только похожесть (TF-IDF или эмбеддер)
* regex OR похожесть, причём похожесть срабатывает только при совместимой модели в тексте (gate)

## Решение
`Matcher.decide`: совпадение regex, или gate и `sim_pos ≥ pos` и `sim_pos − sim_neg ≥ margin`. Пороги подбираются на `eval/labeled.jsonl` при условии recall 1.0 (`eval/run_eval.py`, `eval/sweep.py`).

### Последствия
* Хорошо: regex даёт точность и объяснение, похожесть ловит формулировки, которых нет в правилах (на EXP-001 это строка id 62).
* Плохо: ошибки regex (например id 96) похожесть не исправит, только правило.

### Как проверяем
`tests/test_eval_set.py` (полный recall гибрида), EXP-001.
