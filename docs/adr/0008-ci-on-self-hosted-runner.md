# ADR-0008: эксперименты в CI на своём раннере Лёни, результаты коммитом в results/

## Контекст и проблема
Песочница Telega не тянет torch и MiniLM (EXP-001: dense канал считался только у Лёни руками). У Лёни есть машина с CUDA. Нужно, чтобы каждый push сам прогонял тесты и эксперименты с эмбеддером, а числа возвращались в репо без пересылки руками, и чтобы чужой код не исполнялся на его машине.

## Факторы решения
* реальные dense числа на GPU, воспроизводимо (sha, окружение, команда)
* безопасность машины Лёни: никакого кода из PR и форков, без sudo, без лишних секретов
* результаты читаются агентом прямо из репо
* падение эмбеддера не валит весь прогон (ADR-0005)

## Рассмотренные варианты
* GitHub hosted runner (нет GPU, модель качается каждый раз)
* Лёня гоняет руками и кидает вывод в чат (как было с eval.txt)
* свой раннер, триггер только push в main, результаты JSON коммитом в `results/` и артефактом

## Решение
Свой раннер на машине Лёни с меткой `a2179-gpu` под отдельным пользователем без sudo, зарегистрирован на эту репу. Workflow `experiments.yml` (поставляется как `ci/experiments.yml`, потому что токен Telega не может писать в `.github/workflows`, Лёня включает его одним `git mv` в `.github/workflows/`, команда в docs/ci.md) только на `push` в `main`, `permissions: contents: write`, `concurrency`, `timeout-minutes: 120`. Шаги в отдельных процессах (`ci/run_experiments.py`), dense только после успешного `--check-embedder`, при падении повтор без эмбеддера. `ci/write_results.py` пишет `results/<UTC дата>_<sha>.json` и пушит с `[skip ci]` и rebase retry, `results/**` в `paths-ignore`.

### Последствия
* Хорошо: dense числа на GPU на каждый push, история результатов в git, видно окружение каждого прогона.
* Плохо: кто может пушить в `main`, тот исполняет код на машине Лёни. В `main` добавляются коммиты результатов (перед пушем нужен `git pull --rebase`). Защита ветки с обязательными PR мешает пушу результатов. Изменения самого workflow после включения делает Лёня, не Telega.

### Как проверяем
`tests/test_ci.py` (запись шагов, падение и таймаут дочернего процесса, выбор dense и fallback, сборка JSON, коммит только файла результата, отказ пуша → rebase → повтор, триггеры и права в YAML). YAML разобран PyYAML.
