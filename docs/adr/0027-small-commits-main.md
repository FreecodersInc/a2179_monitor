# ADR-0027: мелкие коммиты сразу в main, следующий кусок только после зелёного CI предыдущего

## Контекст и проблема
Работаем одной веткой main без PR. Раннер один, workflow с `cancel-in-progress`, поэтому новый push убивает идущий прогон. Нужно правило, когда можно пушить, чтобы красное не копилось и нужные прогоны (сбор данных) не обрывались. ADR-0026 решает, какие шаги гонит push, но не порядок пушей.

## Факторы решения
* один раннер, один прогон за раз, cancel-in-progress
* токен не меняет `.github/workflows`
* красное дольше 15 минут откатываем (ADR-0026)

## Рассмотренные варианты
* ветки и PR на каждый кусок
* большие пачки изменений раз в несколько часов
* мелкие коммиты в main с проверкой прошлого прогона

## Решение
Третий вариант. Push без force. Перед следующим куском смотрим прогон предыдущего: зелёный, берём следующий, красный, сначала чиним. Не починили за 15 минут, revert. Код не пушим, пока идёт прогон, который нам нужен (например шаг сбора объявлений), иначе cancel-in-progress его убьёт. Документы и отчёты (`docs`, `experiments`, `work`, `reports/*.md`) идут с `[skip ci]`, их можно пушить в любой момент. Данные ради прохождения проверок не удаляем.

### Как проверяем
каждый коммит кода имеет свой зелёный прогон в `results/<date>_<sha>.json`, ни один нужный прогон не отменён
