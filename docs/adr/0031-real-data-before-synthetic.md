# ADR-0031: сначала реальные данные и чтение глазами, потом ансамбли и CV

## Контекст и проблема
В `eval/labeled.jsonl` 430 строк, из них 59 синтетических, и 31 из 48 позитивов синтетика. Реальных позитивов 17. Все прогоны на этом наборе меряют во многом синтетику, разница между каналами в одну две строки.

## Факторы решения
* числа должны описывать реальный поток
* синтетика завышает (H-08)
* свежие лоты собираются через CI (ADR-0022)

## Рассмотренные варианты
* дальше гонять модели на 430 строках
* копить реальные лоты и вакансии, читать глазами, синтетику считать отдельно

## Решение
Второй вариант. Новые сложные прогоны (ансамбли, большие эмбеддеры, реранк) только когда есть реальная пачка с позитивами, прочитанная глазами. Каждый отчёт показывает числа на реальных строках отдельно. Новых синтетических строк не добавляем. Свежие лоты A2179 копим шагом CI с новым id в `ci/requests/fetch_listings.json`.

### Как проверяем
первая свежая пачка 2026-11-20: 13 новых лотов, 0 позитивов, заморозка 0 FP (T-023). Ждём пачку с позитивами
