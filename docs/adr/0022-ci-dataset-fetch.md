# ADR-0022: сбор сырых объявлений как шаг CI на раннере Лёни

## Контекст и проблема
Для честной проверки (T-023, ADR-0021) и для следующих экспериментов нужны свежие реальные объявления, которых модель и подобранные признаки ещё не видели. Машина Лёни в Сербии может ходить по площадкам, в отличие от среды, откуда часто режут по IP. Сбор должен быть повторяемым шагом CI, а не разовой ручной выгрузкой под один эксперимент.

## Факторы решения
* один и тот же fetch служит всем экспериментам, не только T-023
* к площадкам ходим вежливо: паузы, robots.txt, без лишней нагрузки
* сырые лоты хранятся с датой и источником, дубли отсекаются
* разметка остаётся ручной, шаг CI только собирает сырьё
* площадки выбираем не по вкусу, а по объёму свежих лотов и стабильности вёрстки, плюс одна запасная площадка, чтобы поймать переобучение на стиль одного сайта

## Рассмотренные варианты
* собирать пачку руками, когда понадобится очередной эксперимент
* ходить по площадкам из среды, где часть сайтов режет IP
* сделать fetch шагом CI на раннере Лёни, с правилами выше, и кормить им все эксперименты

## Решение
Третий вариант. Реализовано 2026-11-20 как шаг `fetch_listings` в `ci/run_experiments.py`.

Шаг CI на раннере Лёни сам обходит выбранные площадки, соблюдает robots.txt, держит паузы, дедуплицирует и складывает сырые объявления с датой и источником. Этот запас идёт во все эксперименты, которым нужны свежие лоты. Площадки выбираются по числу свежих объявлений в сутки и по тому, насколько стабильна вёрстка, плюс одна запасная площадка как проверка на переобучение под стиль сайта.

### Последствия
* Хорошо: каждый новый прогон может мерить на том, чего модель ещё не видела, с одной и той же дисциплины сбора.
* Хорошо: раннер в Сербии лучше добирается до местных площадок.
* Плохо: шаг ещё не реализован, до него свежую пачку для T-023 собрать автоматически нельзя. Появится нагрузка на площадки, её надо держать в рамках пауз и robots.txt.

### Как проверяем
Когда шаг появится: в результате прогона видно, сколько лотов собрано, сколько дублей отсеялось, с каких источников, и что запросы не идут против robots.txt. T-023 тогда гоняется на пачке, собранной после заморозки.

## Реализация (2026-11-20)
* Запуск без правки workflow: коммит файла `ci/requests/fetch_listings.json` с новым `id`. Шаг идёт один раз на `id`: если в репо уже есть `results/<base>/reports/fresh_a2179/<id>/candidates.jsonl`, запрос считается выполненным.
* Сбор делает `eval/enrich.py collect` тем же вежливым фетчером, что и монитор (пауза по хосту, KP останавливается на первом отказе, уже размеченное отброшено), с бюджетом времени из запроса.
* Сырые строки и csv лежат в `results/<base>/reports/fresh_a2179/<id>/`, их коммитит `write_results` вместе с результатом.
* Шаг advisory: отказ площадки CI не краснит. В тестах шаг выключен (`A2179_CI_FETCH_LISTINGS=off`), сети из тестов нет.
* Выбор площадок по объёму и запасная площадка пока не сделаны: берём источники из конфига монитора.
