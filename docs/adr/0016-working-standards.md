# ADR-0016: стандарты работы: гипотеза, эксперимент, решение, план, результат

## Контекст и проблема
Работа идёт параллельно у двух людей и агента, часть прогонов на машине Лёни, часть в CI. Нужен один порядок, где что лежит и в какой последовательности делается, чтобы через месяц было понятно, что проверено, чем и почему решено так. ADR-0001 закрепил только формат решений, остальное было по факту.

## Факторы решения
* всё в репо рядом с кодом, версионируется вместе с ним
* каждое число прослеживается до прогона и версии данных
* легко начать, легко продолжить другому участнику

## Рассмотренные варианты
* договорённости в чате
* внешний трекер и wiki
* набор папок в репо с шаблонами и правилами ссылок

## Решение
Третий вариант:
* `experiments/HYPOTHESES.md`: бэклог гипотез, каждая с критерием опровержения, метрикой и данными до прогона. Карта факторов и источники: `experiments/RESEARCH_MAP.md`, ссылки на статьи только проверенные
* `experiments/EXP-NNN_*.md`: один эксперимент по шаблону, версия кода и данных, процедура, результаты только из реальных прогонов с указанием чьих, выводы, угрозы валидности
* `docs/adr/NNNN-*.md`: решения (MADR), не переписываются, заменяются новыми (ADR-0001)
* `work/`: майлстоуны и задачи, у каждой задачи ссылки на H-xx, EXP, ADR и коммиты. Исследовательская задача без EXP не закрывается, решение без ADR тоже
* `results/`: результаты CI (JSON + отчёты + графики), руками не правятся. `reports/`: прогоны руками (например, у Лёни), в EXP пишется, чей прогон
* решения по качеству по стандарту ADR-0013
* порядок: гипотеза в бэклог → задача в `work/` → EXP запись до прогона → прогон (CI или руками) → результаты в EXP → решение в ADR → статус гипотезы и задачи
* тесты не зависят от файлов, которые перезаписываются прогонами (`reports/`, `eval/labeled.jsonl`): для них замороженные копии в `tests/fixtures/`

### Последствия
* Хорошо: любой участник видит, что проверено, что в плане и почему.
* Плохо: больше файлов на каждое изменение, это цена прослеживаемости.

### Как проверяем
Ревью: у каждой закрытой задачи в `work/` есть EXP или ADR, у каждого числа в EXP есть источник.
