# ADR-0011: секреты в CI: по имени из environment experiment, значения нигде не оседают

## Контекст и проблема
Лёня завёл в GitHub environment `experiment` секреты `TG_BOT_TOKEN` и `TG_CHAT_ID` для интеграционных тестов. Раннер на его машине, результаты коммитятся в публичную репу, логи прогона видны. Нельзя, чтобы значение попало в лог, результат или тест, который случайно что то отправит. При этом каждая правка YAML требует ручной копии (ADR-0009).

## Рассмотренные варианты
* `toJSON(secrets)` в шаг: ноль правок YAML для новых секретов, но шаг получает все секреты репы и организации, а GitHub маскирует только целые значения
* каждый секрет по имени: минимум доступа, но новый секрет = копия YAML
* по имени для известных + один секрет `A2179_CI_SECRETS` с JSON для будущих, с белым списком имён и маскированием каждого значения

## Решение
Третий вариант. `environment: experiment` у job. `GITHUB_TOKEN`, `TG_BOT_TOKEN`, `TG_CHAT_ID`, `A2179_CI_SECRETS` по имени. `ci/secrets_env.py` раскрывает JSON только в имена `TG_*`, `SECRET_*`, `A2179_SECRET_*`, каждое значение через `::add-mask::`. `ci/redact.py` записывает только present / absent и вычищает значения (от 4 символов) из хвостов вывода, логов, отчётов и JSON результата. Секреты получает только шаг `tg_integration`, остальные шаги идут без них. Интеграционный тест по умолчанию только читает (`getMe`, `getChat`), отправка по `A2179_CI_TG_SEND=1`.

### Последствия
* Хорошо: новый секрет без правки YAML, значения не попадают ни в git, ни в лог.
* Плохо: секреты в JSON блобе маскирует наш код, а не GitHub целиком. Значения короче 4 символов не вычищаются (помечены в результате). Если у environment есть правила защиты, прогон ждёт их.

### Как проверяем
`tests/test_ci.py`: в YAML только эти четыре секрета и нет `toJSON(secrets)`, в файле результата и отчётах нет значений, шаги без секретов, JSON блоб не может задать `PATH` или `GITHUB_TOKEN`, интеграционный тест пропускается без секретов и не печатает токен в ошибке.
