# ADR-0036: режим вакансий смешивает свой скор с TinyBERT реранком заголовка

## Контекст и проблема
На свежих 150 вакансиях с метками по тексту cv_score даёт AUC 0.608, готовый cross-encoder `cross-encoder/ms-marco-TinyBERT-L2-v2` по заголовку 0.787 (+0.179, 95% 0.093 до 0.269), среднее рангов обоих 0.748. На 462 строках, где cv_score писался, cross-encoder 0.862, cv_score 0.885, среднее рангов 0.925 (EXP-022, H-43). С полным текстом cross-encoder хуже (0.717).

## Рассмотренные варианты
* оставить 0.5 cv_score + 0.5 признаки
* только cross-encoder
* среднее нормированных рангов старого скора и cross-encoder по заголовку

## Решение
Третий вариант: он выше старого скора на обоих наборах (0.748 и 0.925), а один cross-encoder на 462 ниже cv_score. Только заголовок. Модель, файлы и запрос те же, что в EXP-022 (тест сверяет). `job_rerank`: `auto` (по умолчанию, только если модель уже в локальном кэше HF, ничего не качает), `download` (один раз, только если файлы < 50 MiB), `off`. Нет torch или модели: старый скор без изменений. С реранком итог это доля ранга 0..1 внутри прогона, `--min-score` надо ставить по ней.

### Как проверяем
`tests/test_jobmode.py` (смешение рангов, off, те же модель и запрос). Дальше P@10 по оценкам Лёни (T-037).

## Дополнительно
Проверка шла против cv_score варианта A, а режим вакансий использует вариант B плюс признаки. Ссылки: H-43, EXP-022, T-009, T-036.
