# ADR-0015: настройки CI переменными репы, секреты отдельно, полезные дефолты включены

## Контекст и проблема
Каждая правка YAML требует ручной копии у Лёни (токен агента не пишет `.github/workflows`, ADR-0009). Настройки прогона (dense, venv, кэш модели, отправка в Telegram) меняются часто, секреты редко.

## Факторы решения
* новые настройки без правки YAML
* настройки не секретны и видны в логах, секреты никогда
* разумное поведение без настройки вообще

## Рассмотренные варианты
* каждая настройка отдельной строкой `env:` в YAML
* настройки в секретах
* весь `vars` одним JSON (`A2179_CI_VARS: ${{ toJSON(vars) }}`), разбор в `ci/vars_env.py`, секреты по имени (ADR-0011)

## Решение
Третий вариант:
* `ci/vars_env.py` экспортирует только `A2179_CI_*` и `HF_*`, значения экранируются
* `toJSON` допустим для `vars`, потому что они не секретны; для секретов так не делаем (ADR-0011)
* дефолты включены там, где это безопасно и полезно: `A2179_CI_CACHE_MODEL=1` (качает модель, только если её нет в кэше, падение скачивания не роняет setup), `A2179_CI_TG_SEND=1` (одно сообщение в чат за прогон), `A2179_CI_PLOTS=1` (графики после свипа, шаг advisory). Выключаются значением `0`
* таблица всех переменных в `docs/ci.md`

### Последствия
* Хорошо: любая новая `A2179_CI_*` доходит до `ci/run.sh` без копии YAML.
* Хорошо: без настройки прогон уже кэширует модель, шлёт проверочное сообщение и рисует графики.
* Плохо: включённый по умолчанию шаг может зацепить тесты (красный прогон 3b678fa: тест setup с фейковым torch пошёл в сеть за моделью). Отсюда правило: тесты CI выставляют такие переменные явно.

### Как проверяем
`tests/test_ci.py` (vars_env, setup_venv с выключенным и падающим кэшем), поле `workflow_in_sync` в каждом результате.
